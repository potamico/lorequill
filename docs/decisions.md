# Decisions

These decisions refine the [specification](specification.md) where it leaves a choice open. They
describe how Lorequill works today. Code and tests refer to them by number; a change to a decision
is a change to this file.

## Project and distribution

| #   | Topic                              | Decision                                                                                                                                                                                                                                                                                                                                                         |
| --- | ---------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| D2  | Owner, packages, and publisher     | The repository is `potamico/lorequill`. The `@lorequill/*` packages are workspace packages bundled into the extension and the Action; none is published to npm. The extension is `potamico.vscode-lorequill` on the Visual Studio Marketplace and on Open VSX.                                                                                                   |
| D3  | Contacts                           | Code of Conduct reports go to <dev@potamico.org>. Security reports use GitHub's private vulnerability reporting on the repository (`SECURITY.md`).                                                                                                                                                                                                               |
| D34 | Distribution and versioning        | One version for all packages; the engine version is the `@lorequill/checks` version. The Action is a Node 24 JavaScript Action in `action/` with a committed, reproducible bundle, referenced as `potamico/lorequill/action@<commit SHA>`. SARIF upload is a separate workflow step. The profile declares the CI engine in the optional `checks.engine_version`. |
| D5  | Minimum VS Code version            | VS Code 1.110 (`engines.vscode: ^1.110.0`).                                                                                                                                                                                                                                                                                                                      |
| D6  | Language server and editor library | `vscode-languageclient` and `vscode-languageserver` 11.0.0, with `minimatch` overridden to 11.0.3 for an advisory; CodeMirror 6.                                                                                                                                                                                                                                 |
| D20 | Dependency and CI policy           | Runtime dependencies must not use GPL, AGPL, or SSPL licenses. Dependabot ignores `@types/vscode`, major updates of `@types/node`, and TypeScript 6.1 or later (see `development.md`).                                                                                                                                                                           |
| D7  | Reference machine for budgets      | Performance budgets are enforced by the budget tests on the GitHub-hosted CI runners (Linux, macOS, Windows). Their limits leave headroom for slower runners and catch regressions, not small variations.                                                                                                                                                        |
| D9  | German interface texts             | Message keys are English. The German catalog `de-ch.ts` uses Swiss spelling, which a unit test enforces (`ss`, no `ß`); the maintainers review every change to it.                                                                                                                                                                                               |
| D18 | Interface locale                   | All interface texts follow the VS Code display language, with English as the fallback; the German catalog serves every `de` language. The profile's `locale` applies only to content Lorequill writes into the repository, such as commit messages.                                                                                                              |

## Profile and pages

| #   | Topic                     | Decision                                                                                                                                                                                                                            |
| --- | ------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| D11 | Defaults                  | `relative-links` checks anchors by default (`anchors: true`) with `slugify: ascii`, the MkDocs default. `content.exclude` defaults to an empty list; `.git` and `node_modules` are always skipped (D17).                            |
| D12 | Conditions in the profile | `field-format.when` and `reference-field.when` have the shape `{ field, in }`; a collection's `match` has the shape `{ field, equals }`.                                                                                            |
| D13 | Schema limits             | The profile schema bounds every list and string, for example `timeout_seconds` from 1 to 300; `packages/profile/README.md` lists the limits.                                                                                        |
| D14 | Slugs and front matter    | File name slugs drop dots and underscores, are at most 80 characters long, and fall back to `untitled`; reserved names get `-page`. `packages/markdown/README.md` has the details.                                                  |
| D15 | Activation                | The extension activates only when a workspace folder contains `.lorequill/config.yaml`, or when one of its commands runs. The "profile missing" message appears in multi-root workspaces and when the file is deleted later (AT 1). |
| D16 | Glob semantics            | `content.include`, `content.exclude`, and `content.drafts` use `picomatch` on POSIX paths relative to the content root: whole path, case-sensitive, no dot files, no negation, no extglobs.                                         |
| D17 | Page discovery            | Pages are regular `.md` files (any case). Symbolic links are not followed; `.git` and `node_modules` are skipped; a listing stops after 50,000 entries; titles are read from the first 256 KiB.                                     |
| D33 | One content walk          | The Pages tree and the check engine list content files through `listContentFiles` in `@lorequill/profile`: breadth first, so a truncated listing keeps the pages nearest to the root. Both see the same files, also when truncated. |
| D19 | Pages filter              | Case-insensitive substring match in title, file name, or string alias; no accent folding. A directory is shown only if it contains a matching page.                                                                                 |
| D26 | Location of views         | Pages, Properties, and Outline live in Lorequill's own view container in the activity bar; authors may move them with VS Code's view management.                                                                                    |

## Editor

| #   | Topic                      | Decision                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| --- | -------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| D23 | Default editor             | The page editor is a custom text editor with priority `option`. The Pages tree opens pages in it, an editor-title action switches between it and the text editor, and authors who want it for every Markdown file set `workbench.editorAssociations`. README files and Markdown outside the content scope keep the text editor.                                                                                                                                                 |
| D21 | Editing approach and modes | WYSIWYG-style live preview inside CodeMirror, without a block-document round trip; the modes are Edit, Both, and Preview, with a Source toggle.                                                                                                                                                                                                                                                                                                                                 |
| D22 | Rendered preview           | No second parser: the preview is rendered from the shared `mdast` tree through `mdast-util-to-hast` with sanitization. CodeMirror's incremental Lezer parser serves display decorations only, never links or checks.                                                                                                                                                                                                                                                            |
| D27 | Editing budget for 1 MiB   | Edit opens a 1 MiB page within 1 second. In Both and Preview, the editor stays usable while a web worker renders the preview, within 20 seconds in the test guard; rendering never blocks a keystroke.                                                                                                                                                                                                                                                                          |
| D28 | Properties details         | Several matching collections are offered as a choice that only changes the displayed fields. Keys the collection does not define are edited with a widget inferred from their value (text, multi-line text, boolean, list of texts); other values (numbers, mappings) are read-only. A list field holding a single text is shown as a one-item list; a date field holding other text is edited as text; clearing a required or unknown field keeps the key with an empty value. |

## Checks

| #   | Topic                        | Decision                                                                                                                                                                                                                                                       |
| --- | ---------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| D8  | Heading anchors              | Both `slugify` variants replicate Python-Markdown exactly: `ascii` is the default `toc` slugify of MkDocs, `unicode` is `pymdownx.slugs` with lower-case Unicode. Fixtures are generated with the real libraries; `mkdocs build --strict` stays authoritative. |
| D10 | `unique-field` normalization | Values are compared as text after Unicode NFC, trimming, collapsing whitespace runs, and locale-independent lower case; `BOK-1` and `bok-1` are duplicates.                                                                                                    |
| D24 | Diagnostics timing           | Diagnostics update automatically after a pause in typing and on save, incrementally; **Check Pages** runs a complete check with a summary.                                                                                                                     |

## Git and review

| #   | Topic               | Decision                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| --- | ------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| D4  | Git access          | Hybrid: the VS Code Git extension API for discovery, status, staging, refresh, and push, with VS Code's credentials; the Git binary from that API, called with argument arrays, for the index tree identity, staged blobs, commits, and tree verification. The API offers no tree identities.                                                                                                                                                                                                                                                                |
| D29 | Index tree identity | The staged tree ID is computed from `git ls-files --stage -z --debug` in Git's tree format (SHA-1 or SHA-256), without intent-to-add entries, as a commit does. `git write-tree` is not used: it rewrites the index and can run the `post-index-change` hook and content filters. Unit tests compare the result with `git write-tree`; a mismatch after a commit fails safe as **Commit not verified**.                                                                                                                                                      |
| D25 | Commit dialog       | A native quick pick and input box with VS Code's diff editor, not a webview.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| D30 | Commit check        | The profile is read from the checked tree, as CI reads it from the commit; the working-tree profile is used only when `.lorequill/config.yaml` is not tracked, and the message prompt says so. An invalid staged profile blocks the commit. No commit on a detached `HEAD` or with merge conflicts. Partially staged files stay as they are; pre-staged files outside the content root need confirmation. The review state is per repository and persisted; a later verified commit or a passing check of the current commit clears **Commit not verified**. |
| D31 | Submit              | The remote is the branch upstream's, else `origin`, else chosen. The pull request targets the same repository (no fork workflow) and needs push access. The base branch is `review.base_branch`, else the host's default branch. The title defaults to the single commit's subject or the branch name and is editable. A closed or merged review of the same branch blocks submission until a new branch is used. The GitHub end-to-end test is opt-in through environment variables.                                                                        |
| D32 | Flows behind ports  | Commit, Check Commit, and Submit are pure flows in `src/core/git/commit-flow.ts` and `src/core/host/submit.ts`, with ports for prompts and repository operations. One `RepositoryContext` chooses folder and repository for all Git actions. Dialogs are injected prompt interfaces; the internal test API with the mock host exists only in VS Code's test mode.                                                                                                                                                                                            |
